## 1. 任务要求解读

打开课程设计 PDF 第 6 章，**任务 1-2**：

> **基于词法分析程序和自底向上的语法分析程序，基于 S-翻译模式，编写 PL/0 编译程序的语义分析程序，并生成四元式形式的中间代码。**

### 关键术语

| 术语 | 说明 |
|------|------|
| **S-翻译模式**（S-Translation Scheme） | 所有语义动作放在产生式右部的**末尾**，属性值自底向上传递（综合属性） |
| **自底向上** | 尽管实现用了递归下降（自顶向下），但语义动作在"归约时"执行，模仿了 LR 分析器的 S-翻译模式 |
| **四元式**（Quadruple） | `(op, arg1, arg2, result)` 形式的中间代码 |

### 必做功能

1. 分析 PL/0 程序段：变量声明、赋值语句、条件语句（if-then-else）、循环语句（while-do）、过程调用
2. 生成控制流跳转和临时变量管理（回填技术）
3. 正确处理语义错误：未声明变量、重复声明、类型不匹配

## 2. 项目整体架构

### 2.1 三阶段流水线

```
源代码 (.pl0)
    │
    ▼
┌─────────────┐    Token流    ┌───────────────┐   四元式    ┌─────────────┐
│  Lexer      │ ────────────► │  LR1Parser    │ ──────────► │  输出结果    │
│  词法分析    │               │  语法+语义分析  │             │   Main      │
│  (DFA手工)   │               │  (递归下降+    │             │             │
│             │               │   S-翻译模式)  │             │             │
└─────────────┘               └───────┬───────┘             └─────────────┘
                                      │
                           ┌──────────┼──────────┐
                           ▼          ▼          ▼
                    ┌──────────┐ ┌────────┐ ┌──────────┐
                    │ 符号表   │ │ 四元式  │ │ 错误列表  │
                    │ Symbol   │ │ Quad   │ │ Semantic  │
                    │ Table    │ │ Manager│ │ Error     │
                    └──────────┘ └────────┘ └──────────┘
```

### 2.2 设计原则

1. **模块化分离**：词法分析、语法分析、语义分析分属独立包，职责清晰
2. **S-翻译模式**：在递归下降过程中同步执行语义动作，归约时发射四元式
3. **单遍扫描**：一次遍历源代码即完成全部三阶段分析和代码生成
4. **错误恢复**：遇到错误不停止，继续分析以发现更多错误

### 2.3 包结构

| 包 | 类 | 职责 | 分离原因 |
|----|-----|------|----------|
| `lexer` | `Token`, `LexerError`, `Lexer` | 字符流 → Token 流 | 词法规则独立，修改不影响上层 |
| `parser` | `SemanticError`, `LR1Parser` | Token 流 → 四元式 | 核心语义逻辑集中 |
| `symbol` | `Symbol`, `SymbolTable` | 符号的声明、查找、作用域管理 | 作为独立服务，供 parser 查表 |
| `quadruple` | `Quadruple`, `QuadrupleManager` | 四元式存储、发射、回填 | 四元式格式变化不影响其他模块 |
| `main` | `Main` | 主控、三种运行模式、输出 | 分离可复用逻辑 |

## 3. 词法分析器 — Lexer.java

### 设计思路

手工编写 DFA（确定有限自动机），逐行扫描字符流。每个字符触发状态转移，最终到达接受状态决定 Token 类型。

### 核心算法流程

```
for 每一行:
   跳过空白
   '/'  判断 → //(跳过整行) 或 /*(多行注释过到行尾或跨行)
   字母/_ → 读完整单词 → 查 KW 集合区分关键字/标识符
   数字   → 读完整数字 → 后跟字母则报 BadToken(如 2a)
   :=/<=/>= → 双字符运算符
   + - * / = # < > → 单字符运算符
   ( ) ; , . → 界符
   其他字符 → 报 BadChar 错误
```

### 关键字集合

```java
static final Set<String> KW = new HashSet<>(Arrays.asList(
    "const", "var", "procedure", "call", "begin", "end",
    "if", "then", "else", "while", "do", "read", "write", "odd"
));
```

PL/0 共 **14 个关键字**。

### 标识符 vs 关键字区分策略：先匹配再查表

```java
// 1. 按标识符规则读入完整单词
if (Character.isLetter(ch) || ch == '_') {
    int s = col;
    while (col < line.length()
        && (Character.isLetterOrDigit(line.charAt(col)) || line.charAt(col) == '_'))
        col++;
    String w = line.substring(s, col);

    // 2. 查关键字集合
    if (KW.contains(w)) {
        toks.add(new Token("KW", w, lineno));    // 关键字
    } else {
        if (w.length() > 8)
            errs.add(new LexerError("LongIdent," + w, lineno));
        toks.add(new Token("Ident", w, lineno));  // 标识符
    }
}
```

### 词法错误类型

| 错误 | 举例 | 说明 |
|------|------|------|
| `BadChar` | `@`, `&`, `!` | 不在 PL/0 字符集中的非法字符 |
| `BadToken` | `2a`, `1abc` | 数字开头后跟字母的非法单词 |
| `LongIdent` | `longname1`（>8 字符） | 标识符超长 |
| `NumOverflow` | `123456789`（>8 位） | 数字越界 |

## 4. 符号表管理 — SymbolTable.java

### 设计思路

**栈式作用域**（类似函数嵌套调用），用 `List<Map<String, Symbol>>` 实现。

### 数据结构

```java
private List<Map<String, Symbol>> scopes = new ArrayList<>();
// scopes[0] = 全局作用域
// scopes[1] = 第一层嵌套过程的作用域
// ...
private List<Symbol> all = new ArrayList<>(); // 所有符号的扁平列表（用于输出）
```

### 核心方法

```java
// 进入新作用域（push）
public void enterScope() {
    scopes.add(new HashMap<>());
}

// 退出当前作用域（pop）
public void exitScope() {
    if (scopes.size() > 1)
        scopes.remove(scopes.size() - 1);
}

// 从内向外逐层查找 —— 静态（词法）作用域
public Symbol lookup(String name) {
    for (int i = scopes.size() - 1; i >= 0; i--) {
        Map<String, Symbol> s = scopes.get(i);
        if (s.containsKey(name)) return s.get(name);
    }
    return null;
}

// 当前层添加符号，重复则返回 false
public boolean add(String name, String kind, String value) {
    Map<String, Symbol> cur = scopes.get(scopes.size() - 1);
    if (cur.containsKey(name)) return false;  // 重复声明
    Symbol s = new Symbol(name, kind, value, level(), 0);
    cur.put(name, s);
    all.add(s);
    return true;
}
```

### 必讲知识点

- **栈式作用域**：`enterScope/exitScope` 对应过程的进入和退出，类似调用栈
- **从内向外查找**：内层同名变量会"遮蔽"外层变量（静态作用域 / 词法作用域）
- **重复声明检测**：`add()` 只在当前层查重，不同层允许同名

## 5. 四元式管理器 — QuadrupleManager.java

### 数据结构

```java
private List<Quadruple> quads = new ArrayList<>();   // 四元式列表
private int tempCount = 0;                           // 临时变量计数器 T1, T2...
private int labelCount = 0;                          // 标签计数器 $1, $2...
private Map<String, List<Integer>> pending;            // 待回填表
```

### 核心方法

| 方法 | 功能 | 说明 |
|------|------|------|
| `emit(op, a1, a2, r)` | 发射一条完整的四元式，返回 1-based 序号 | 基本发射 |
| `emit(op)` | 简化版，全部填 `_` | 便捷重载 |
| `newTemp()` | 创建新临时变量 `T1, T2...` | 临时变量管理 |
| `newLabel()` | 创建新标签 `$1, $2...` | 回填 |
| `emitWP(op, a1, a2, label)` | 发射同时将序号记入 `pending[label]` | 回填 |
| `patch(label)` | 将 `pending[label]` 中所有四元式的 `result` 域改为当前位置 | 回填 |

### 回填技术原理

**问题**：条件语句 `if cond then stmt` 中，条件为假时要跳转到 then 之后的位置，但解析时还不知道那个位置在哪里。

**解决**：两步走 —— 先占位，后补全。

```
emitWP("j=", cp, "0", fl)
    ↓ 发射一条四元式 (j=, cp, 0, $1)
    ↓ 同时将 7 记入 pending["$1"] = [7]

// ... 解析 then 子句 ...

patch(fl)
    ↓ 此时四元式列表长度为 10
    ↓ 当前位置 = 10 + 1 = 11
    ↓ 将 pending["$1"] 中的第7条四元式 result 改为 "11"
    ↓ (j=, cp, 0, 11)  ← 跳转目标补全
```

## 6. 语法+语义分析 — LR1Parser.java

### 6.1 递归下降入口链

```
parse()                       程序 → 块 .
  │
  └─ parseBlock()            块 → [const] [var] {proc} 语句
       │
       ├─ parseConst()       const 声明（递归解析逗号分隔的多常量）
       ├─ parseVar()         var 声明（递归解析逗号分隔的多变量）
       ├─ parseProc()        过程声明（进入新作用域 → 递归 parseBlock）
       └─ parseStmt()        语句分发
            │
            ├─ parseAssign()   赋值 id := expr ;
            ├─ parseIf()       if cond then stmt [else stmt]
            ├─ parseWhile()    while cond do stmt
            ├─ parseRead()     read(id) ;
            ├─ parseWrite()    write(expr) ;
            ├─ parseCall()     call id ;
            └─ parseCond()     条件 odd expr | expr relop expr

parseExpr() → parseETail(parseTerm())
  parseTerm() → parseTTail(parseFact())
    parseFact() → id | num | (expr)
```

**如何体现 S-翻译模式**？—— 每个语法成分解析完毕时执行语义动作，即**产生式末尾**调用 `qm.emit()`。

### 6.2 赋值语句 — S-翻译模式示范

**产生式**：`赋值语句 → id := 表达式 ;`

**语义动作**（在产生式末尾依次执行）：
1. 查符号表验证 id 已声明且为变量
2. 解析表达式，得到存放结果的临时变量名
3. `emit(":=", 临时变量, "_", id_name)`

```java
private void parseAssign() {
    Token id = next();
    String n = id.value;
    int ln = id.lineno;

    // 语义动作 ①：查符号表验证声明和类型
    Symbol s = st.lookup(n);
    if (s == null) {
        err("Undecl " + n, ln);
    } else if (!"var".equals(s.kind)) {
        err(n + " not var", ln);
    }

    if (!mat("ASGN")) { /* 错误恢复... */ return; }

    // 语义动作 ②：解析表达式
    String ep = parseExpr();

    if (!mat("SEMI")) { err("Expect ;", ln); return; }

    // 语义动作 ③：发射四元式  ← 产生式末尾！
    qm.emit(":=", ep, "_", n);
}
```

### 6.3 条件语句 — 回填技术

**产生式**：`条件语句 → if 条件 then 语句 [else 语句]`

**流程**：

```
                    ┌──────────────────────────┐
                    │  newLabel(): fl, el       │  ← 创建假标签和出口标签
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  parseCond() → cp         │  ← 解析条件，得到临时变量
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  emitWP("j=", cp, 0, fl)  │  ← 条件为假 → 跳 fl（占位）
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  parseStmt() /* then 子句 */│
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  emitWP("j", "_", "_", el)│  ← then 结束 → 跳 el（占位）
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  patch(fl)                │  ← 回填 fl = 当前位置
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  [可选] parseStmt(else子句)│
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  patch(el)                │  ← 回填 el = 当前位置
                    └──────────────────────────┘
```

```java
private void parseIf() {
    next();                              // 消费 if
    String fl = qm.newLabel();           // false label
    String el = qm.newLabel();           // exit label

    String cp = parseCond();             // 解析条件 → cp

    if (!mat("THEN")) { err("Expect THEN"); return; }

    qm.emitWP("j=", cp, "0", fl);       // 条件为假 → fl
    parseStmt();                         // then 子句
    qm.emitWP("j", "_", "_", el);       // then 结束 → el（跳过 else）
    qm.patch(fl);                        // fl 回填到当前位置

    if (mat("ELSE")) parseStmt();        // else 子句（可选）

    qm.patch(el);                        // el 回填到当前位置
}
```

**示例**：`if a <= 10 then c := b + a;`

```
(1) (<=, a, 10, T1)        ← 条件计算结果
(2) (j=, T1, 0, 5)         ← 假则跳到 (5) (经回填)
(3) (+, b, a, T2)          ← then 子句
(4) (:=, T2, _, c)
                            ← patch($1): (2) 的 result 改为 5
                            ← patch($2): 无 else，出口就是这里
(5) ...后续代码...
```

### 6.4 循环语句 — 回填技术

**产生式**：`循环语句 → while 条件 do 语句`

**流程**：

```
                    ┌──────────────────────────┐
                    │  newLabel(): ls           │  ← 循环开始标签
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  patch(ls) → loopStart    │  ← 记录循环入口
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  newLabel(): ex            │  ← 出口标签
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  parseCond() → cp          │
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  emitWP("j=", cp, 0, ex)  │  ← 条件为假 → 跳出
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  parseStmt() /* 循环体 */  │
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  emit("j",_,_,loopStart)  │  ← 跳回循环开始
                    └──────────┬───────────────┘
                               ▼
                    ┌──────────────────────────┐
                    │  patch(ex)                │  ← 出口回填
                    └──────────────────────────┘
```

```java
private void parseWhile() {
    next();                                    // 消费 while
    String ls = qm.newLabel();
    int loopStart = qm.patch(ls);              // 记录循环入口

    String ex = qm.newLabel();                 // 出口标签
    String cp = parseCond();                   // 解析条件

    if (!mat("DO")) { err("Expect DO"); return; }

    qm.emitWP("j=", cp, "0", ex);              // 假则跳出
    parseStmt();                                // 循环体
    qm.emit("j", "_", "_", String.valueOf(loopStart)); // 跳回入口
    qm.patch(ex);                              // 出口回填
}
```

**示例**：`while b # 0 do begin call p; read(b); end`

```
(1) (#, b, 0, T1)         ← 循环开始（patch 记录位置）
(2) (j=, T1, 0, 6)       ← 假则跳到 (6)（出口）
(3) (call, p, _, _)       ← 循环体
(4) (read, b, _, _)
(5) (j, _, _, 1)          ← 跳回 (1) 继续循环
(6) ...                    ← 出口（patch 回填到这里）
```

### 6.5 表达式解析 — 左递归消除

#### 问题

原始文法存在**左递归**：

```
表达式 → 表达式 + 项 | 项      ← 左递归
项     → 项 * 因子 | 因子     ← 左递归
```

直接递归下降时，`parseExpr()` 会先调 `parseExpr()`，导致**无限递归**。

#### 解决方案：改写为尾递归

```
表达式 → 项 {+ 项 | - 项}
parseExpr() → parseETail(parseTerm())

项 → 因子 {* 因子 | / 因子}
parseTerm() → parseTTail(parseFact())
```

#### 代码实现

```java
// 表达式 → 项 {+ 项 | - 项}
private String parseExpr() {
    return parseETail(parseTerm());    // 先解析一个项
}

private String parseETail(String l) {
    Token t = peek();
    if (t == null) return l;
    String s = sym(t);
    if (s.equals("PLUS") || s.equals("MIN")) {
        next();                         // 消费 + 或 -
        String rr = parseTerm();        // 解析右边的项
        String r = qm.newTemp();        // 新临时变量
        qm.emit(s.equals("PLUS") ? "+" : "-", l, rr, r);
        return parseETail(r);           // 尾递归继续
    }
    return l;                           // 没有更多运算符 → 返回
}

// 项 → 因子 {* 因子 | / 因子}
private String parseTerm() {
    return parseTTail(parseFact());
}

private String parseTTail(String l) {
    Token t = peek();
    if (t == null) return l;
    String s = sym(t);
    if (s.equals("MUL") || s.equals("DIV")) {
        next();
        String rr = parseFact();
        String r = qm.newTemp();
        qm.emit(s.equals("MUL") ? "*" : "/", l, rr, r);
        return parseTTail(r);
    }
    return l;
}
```

#### 完整解析示例：`a + b * c - d`

```
parseExpr()
  └ parseTerm()
       └ parseFact() → "a"
       └ parseTTail("a"): peek 是 + → 返回 "a"
  └ parseETail("a")
       ├─ 遇到 +，消费 +
       ├─ parseTerm()
       │    └ parseFact() → "b"
       │    └ parseTTail("b"):
       │         ├─ 遇到 *，消费 *
       │         ├─ parseFact() → "c"
       │         ├─ emit(*, b, c, T1) → T1
       │         └ parseTTail(T1): peek 是 - → 返回 T1
       ├─ emit(+, a, T1, T2) → T2
       └ parseETail(T2)
            ├─ 遇到 -，消费 -
            ├─ parseTerm()
            │    └ parseFact() → "d"
            │    └ parseTTail("d") → 返回 "d"
            ├─ emit(-, T2, d, T3) → T3
            └ parseETail(T3): peek 无 → 返回 T3

结果：T3 = a + (b * c) - d   ✓ 乘法优先于加法
```

#### 关键知识点

| 知识点 | 说明 |
|--------|------|
| **左递归消除** | `E → E + T | T` 改写为 `E → T {+ T}`，避免无限递归 |
| **优先级保证** | `parseExpr → parseTerm → parseFact` 层层嵌套，乘除先于加减，括号内先算 |
| **左结合** | 尾递归的从左到右顺序自然实现运算符的左结合性 |
| **临时变量链** | 每个运算分配新 `T_n`，形成"变量名链"传递中间结果 |

### 6.6 因子解析

```java
private String parseFact() {
    Token t = peek();
    if (t == null) { err("Unexpected EOF"); return "_"; }
    String s = sym(t);

    if (s.equals("id")) {                  // 标识符
        Token id = next();
        String n = id.value;
        Symbol ss = st.lookup(n);          // 查符号表
        if (ss == null) err("Undecl " + n, id.lineno);
        return n;
    }

    if (s.equals("num")) {                 // 数字常量
        return next().value;
    }

    if (s.equals("LP")) {                  // (表达式)
        next();
        String e = parseExpr();
        if (!mat("RP")) err("Expect )");
        return e;
    }

    err("Bad expr start " + t.value, t.lineno);
    return "_";
}
```

## 9. 验收问答模拟

### Q1：你为什么选择递归下降分析法？

递归下降分析法是手工编写最直观的自顶向下语法分析方法。每个非终结符对应一个方法，代码结构和文法规则一一对应，可读性和可维护性都很好。配合 S-翻译模式，可以在解析过程中直接插入语义动作，实现一遍扫描完成语法分析和代码生成。

### Q2：什么是 S-翻译模式？和 L-翻译模式的区别？

S-翻译模式（S-Translation Scheme）是语法制导翻译的一种形式，核心特征是：

- 所有语义动作都放在产生式的**末尾**
- 属性值通过**综合属性**自底向上传递

与 L-翻译模式的区别：

| 特性 | S-翻译模式 | L-翻译模式 |
|------|-----------|-----------|
| 属性方向 | 仅综合属性（子→父） | 综合 + 继承（父→子） |
| 语义动作位置 | 仅产生式末尾 | 产生式任意位置 |
| 适用分析 | 自底向上（LR） | 自顶向下（LL） |
| 本项目 | ✅ 使用 | ❌ |

本项目虽然是递归下降（自顶向下）的架子，但每个语法成分的语义动作都在解析完该成分后执行，符合 S-翻译模式"归约时执行"的思想。

### Q3：回填技术是怎么实现的？

回填（Backpatching）解决控制流语句中**跳转目标未知**的问题：

1. **`newLabel()`**：生成一个符号标签（如 `$1`）
2. **`emitWP()`**：发射跳转四元式，同时把它的序号记入 `pending[label]` 列表
3. **`patch()`**：解析到跳转目标位置时，遍历 `pending[label]` 中的所有四元式，将它们的 `result` 域更新为当前位置

这样，`if` 和 `while` 的前向跳转目标无需预先知道，解析到目标位置时回填即可。

### Q4：你怎么处理左递归？

原始表达式文法 `E → E + T | T` 存在左递归，直接递归下降会陷入无限递归。我将它改写为尾递归形式 `E → T {+ T}`：

- `parseExpr()` 先调 `parseTerm()` 解析一个项
- 然后 `parseETail()` 循环处理后续的 `+ 项` 或 `- 项`

同样的方法应用于项（`T → F {* F}`），确保乘除先于加法。

### Q5：表达式 `a + b * c` 生成什么四元式？如何保证优先级？

生成：
```
(*, b, c, T1)    ← 乘法先
(+, a, T1, T2)   ← 加法后
```

优先级通过方法调用的嵌套层次保证：
```
parseExpr() → parseETail(parseTerm())
                  parseTerm() → parseTTail(parseFact())
```
`parseExpr()` 调用 `parseTerm()`，`parseTerm()` 内部会先把 `b * c` 解析完并发射乘法四元式，之后 `parseETail()` 才处理加法运算符，自然实现了"乘法先于加法"。

### Q6：`if a <= 10 then c := b + a;` 生成的四元式？

```
(1) (<=, a, 10, T1)        ← 条件计算：T1 = (a <= 10)
(2) (j=, T1, 0, 5)         ← 假则跳到 (5)
(3) (+, b, a, T2)          ← then 子句
(4) (:=, T2, _, c)
                            ← 回填：$1→5, $2→5
(5) ...后续代码...
```

### Q7：符号表为什么用 `List<Map>` 而不是一个全局 Map？

`List<Map<String, Symbol>>` 实现了**栈式作用域**。`enterScope()` push 一个新的 HashMap（进入嵌套过程），`exitScope()` pop（退出过程）。

`lookup()` 从栈顶向下遍历，符合"从内向外"的静态作用域规则。每个 HashMap 存当前层的符号名→条目映射，保证 O(1) 查重。

如果用一个全局 Map 加"level"字段，退出作用域时需要扫描删除，而且无法处理"内层遮蔽外层"的语义。

### Q8：你们做了哪些错误恢复？

1. **词法错误**：遇到非法字符继续扫描，仅记录错误不下发
2. **语法"多吞"恢复**：`parse()` 在 `parseBlock()` 后有一个 while 循环，跳过残留 Token 直到找到 `.`
3. **语义错误**：未声明变量时返回 `"_"` 占位，不中断解析；缺少分号时跳过无关 Token 直到分号或有意义的关键字

## 10. 与 PDF 期望输出的差异说明

你的项目实际输出与 PDF 第 6.4 节的示例输出有三处差异，**验收时老师可能会问到**：

| # | 方面 | PDF 期望输出 | 本项目实际输出 | 原因 |
|---|------|-------------|---------------|------|
| 1 | 条件处理 | `(j<=,a,10,$8)` 直接关系+跳转 | `(<=,a,10,T1)` + `(j=,T1,0,12)` 拆两步 | 本项目条件统一返回临时变量，由 emitWP 单独处理跳转，职责更单一 |
| 2 | 赋值处理 | `(+,b,a,c)` 直接写目标变量 | `(+,b,a,T2)` + `(:=,T2,_,c)` 分计算和赋值两步 | 严格遵守三地址码：每个四元式只做一件事 |
| 3 | 过程出口 | 有 `(ret,_,_,_)` | 无 ret | 本项目过程结束后不额外生成 ret 四元式，以 `(procedure, ...)` 标记过程区域 |

### 建议的应答策略

> "PDF 列出的是一种参考性的四元式格式示例。我的实现采用了更规范的三地址码形式：条件运算结果先存入临时变量，再通过 `j=` 判断跳转（类似标准编译教材中的做法）；赋值操作严格区分表达式求值（产生临时变量）和变量赋值（`:=`），每个四元式只执行一个原子操作。这样的设计有利于后续的代码优化和寄存器分配。如果希望完全匹配 PDF 格式，可以合并 emit 调用，但现在的设计更符合编译原理的三地址码规范。"
