# 设计原理

> 项目：PL0_SemanticAnalyzer_STranslation  
> 采用 **S-翻译模式（S-Translation Scheme）** 的自底向上语义分析器

---

## 1. 总体架构设计

```
源代码 (PL/0)
    │
    ▼
┌──────────┐     Token流     ┌──────────────┐     四元式     ┌──────────┐
│  词法分析 │ ───────────────►│ 语法+语义分析 │ ──────────────►│ 输出结果 │
│  (Lexer)  │                 │ (LR1Parser)   │               │ (Main)   │
└──────────┘                 └───────┬───────┘               └──────────┘
                                     │
                          ┌──────────┼──────────┐
                          ▼          ▼          ▼
                   ┌──────────┐ ┌────────┐ ┌──────────┐
                   │ 符号表   │ │ 四元式 │ │ 错误处理 │
                   │(SymbolTbl)│ │(QuadMgr)│ │(Err List)│
                   └──────────┘ └────────┘ └──────────┘
```

### 设计原则

1. **模块化分离**：词法分析、语法分析、语义分析分属独立包，职责清晰
2. **S-翻译模式**：在递归下降语法分析的过程中同步执行语义动作，归约时计算综合属性
3. **单遍扫描**：一次遍历源代码即可完成词法分析→语法分析→语义分析→四元式生成
4. **错误恢复**：遇到错误不中断，尽可能继续分析以发现更多错误

## 2. 词法分析设计原理

### 2.1 基于 DFA 的手工词法分析

不依赖 Flex 等自动生成工具，而是手工编写 DFA 识别逻辑：

```
源代码字符流
    │
    ▼
┌──────────────────────────────────────────────────────┐
│                    DFA 状态转移                        │
│                                                        │
│  空白 → 跳过                                           │
│  / → 判断 //(单行注释) 或 /*(多行注释)                  │
│  字母/_ → 识别标识符/关键字                              │
│  数字 → 识别无符号整数                                   │
│  := / <= / >= → 双字符运算符                            │
│  + - * / = # < > & @ ! → 单字符运算符                   │
│  ( ) ; , . → 界符                                       │
│  其他 → 非法字符错误                                     │
└──────────────────────────────────────────────────────┘
    │
    ▼
  Token流
```

### 2.2 关键字与标识符的区分

采用 **先匹配再查表** 策略：
1. 按标识符规则读入完整单词
2. 查预定义关键字集合 `KW`
3. 存在 → 标记为关键字 Token；不存在 → 标记为标识符 Token

### 2.3 注释处理

- 单行注释 `//`：遇到后跳过当前行剩余字符
- 多行注释 `/* */`：设置 `inBlock` 标志，跨行扫描直到遇到 `*/`

## 3. 语法分析设计原理

### 3.1 递归下降分析法

采用手工编写的递归下降解析器，每个非终结符对应一个解析方法：

| 非终结符 | 方法 | 策略 |
|---------|------|------|
| 程序 | `parse()` | 调用 `parseBlock()` + 匹配 `.` |
| 块 | `parseBlock()` | 依次尝试常量/变量/过程/语句 |
| 常量声明 | `parseConst()` | 匹配 `const`，循环解析常量定义 |
| 变量声明 | `parseVar()` + `parseIds()` | 匹配 `var`，递归解析逗号分隔的标识符 |
| 过程声明 | `parseProc()` | 匹配 `procedure`，递归调用 `parseBlock()` |
| 语句 | `parseStmt()` | 根据 lookahead 符号分发到子方法 |
| 表达式 | `parseExpr()` → `parseETail()` | 消除左递归后尾递归解析 |
| 条件 | `parseCond()` | 处理 `odd` 或关系表达式 |
| 因子 | `parseFact()` | 处理 id / num / (expr) |

### 3.2 左递归消除

原始文法中表达式和项存在左递归：

```
表达式 → 表达式 + 项 | 项        (左递归)
项     → 项 * 因子 | 因子       (左递归)
```

改造为尾递归形式：

```
表达式 → 项 {+ 项}              (右递归)
表达式 → parseETail(parseTerm())
项     → 因子 {* 因子}          (右递归)
项     → parseTTail(parseFact())
```

### 3.3 SELECT 集与预测分析

每个解析方法通过 `peek()` 获取下一个 Token 的符号类型（sym），根据 lookahead 决定走哪个分支。例如 `parseStmt()` 的决策逻辑：

| lookahead 符号 | 对应语句类型 |
|---------------|-------------|
| `id` | 赋值语句 |
| `READ` | 读语句 |
| `WRITE` | 写语句 |
| `CALL` | 过程调用 |
| `BEG` | 复合语句 |
| `IF` | 条件语句 |
| `WHILE` | 循环语句 |
| `ODD` | 条件表达式 |
| 其他 | 空语句（ε） |

## 4. 语义分析设计原理

### 4.1 S-翻译模式

**S-翻译模式（S-Translation Scheme）** 是语法制导翻译的一种形式，其中：

- 每个产生式关联一组语义动作
- **语义动作位于产生式右部的末尾**
- 属性值自底向上传递（综合属性）
- 归约时执行语义动作

与 L-翻译模式的区别：

| 特性 | S-翻译模式 | L-翻译模式 |
|------|-----------|-----------|
| 属性方向 | 仅综合属性 | 综合 + 继承 |
| 计算时机 | 归约时 | 任意位置 |
| 适用分析 | 自底向上（LR） | 自顶向下（LL） |
| 本项目 | ✅ 使用 | ❌ |

### 4.2 四元式生成

每个语义动作生成一条或多条四元式。以赋值语句为例：

```
产生式：赋值语句 → id := 表达式 ;
语义动作：
  ① 查符号表获取 id 的地址
  ② 解析表达式，得到临时变量 T
  ③ emit(":=", T, "_", id)
```

生成的典型四元式序列：
```
( :=, T2, _, c )     // c := b + a
```

### 4.3 回填技术（Backpatching）

条件语句和循环语句的跳转目标在解析时未知，采用回填技术：

**条件语句（if）流程：**
```
1. 解析条件，生成条件结果 cp
2. 创建标签 fl（false label）和 el（exit label）
3. 发射 j= cp 0 fl    ← 条件为假时跳转（暂填 fl 占位）
4. 解析 then 语句
5. 发射 j _ _ el       ← 跳过 else 分支（暂填 el 占位）
6. patch(fl)           ← 回填 fl 为当前四元式编号+1
7. 解析 else 语句（可选）
8. patch(el)           ← 回填 el 为当前四元式编号+1
```

**循环语句（while）流程：**
```
1. 创建标签 ls（loop start）
2. patch(ls)           ← 标记循环开始位置
3. 解析条件，生成 cp
4. 创建标签 ex（exit label）
5. 发射 j= cp 0 ex     ← 条件为假跳出
6. 解析循环体语句
7. 发射 j _ _ ls        ← 跳回循环开始
8. patch(ex)           ← 回填出口
```

### 4.4 符号表管理

采用 **栈式作用域（Stack-Based Scope）**：

```
全局作用域 ─┬─ const a = 10
           ├─ var b, c
           └─ procedure p ─── 作用域 ─┬─ var x
               (enterScope)    (exitScope)
```

关键操作：
- `enterScope()`：压入新字典，进入过程/块的作用域
- `exitScope()`：弹出当前字典，退出作用域
- `add(name, kind)`：当前作用域添加符号，重复返回 false
- `lookup(name)`：从内向外逐层查找，支持嵌套作用域

## 5. 模块间接口设计

```
Lexer.tokenize(code) ────────────────► List<Token>
                                            │
                                            ▼
LR1Parser.parse(tokens, lexErrs) ──────────► Map<String, Object>
  ├── 使用 SymbolTable 管理符号              ├─ "errs" → List<SemanticError>
  ├── 使用 QuadrupleManager 生成四元式        ├─ "lexerrs" → List<LexerError>
  └── LR 递归下降解析 + 语法制导翻译           ├─ "quads" → String (四元式文本)
                                              └─ "symtbl" → String (符号表文本)
```

## 6. 错误处理设计

| 错误类型 | 检测位置 | 处理策略 |
|---------|---------|---------|
| 非法字符 @ & ! | 词法分析 | 记录错误 Token，继续分析 |
| 数字开头的单词 2a | 词法分析 | 记录 BadToken 错误 |
| 标识符超长 >8 | 词法分析 | 记录 LongIdent 错误 |
| 数字越界 >8位 | 词法分析 | 记录 NumOverflow 错误 |
| 未声明变量 | 语义分析 | 记录 Undecl 错误，用占位值 "_" 继续 |
| 重复声明 | 语义分析 | 记录 Dup 错误 |
| 语法错误（缺;缺)等） | 语法分析 | 报错并尝试恢复 |
